# fitness_beats_truth

**同じ感覚から、違う選択が生まれる。**

Donald D. Hoffman らの研究をもとにした、ブラウザだけで動く進化ゲーム実験室です。緑の **F / Fitness-only**、桃色の **T / Truth（MAP）**、必要に応じて紫の **H / Hybrid** が、固定サイズの個体群で出生・死亡を繰り返します。

`index.html` に JavaScript・CSS・Canvas 描画・効果音合成・説明・数値テストをすべて内蔵しています。CDN、外部ライブラリ、画像、フォント、音声ファイル、サーバー側処理は使いません。配布物は次の2ファイルだけです。

```text
fitness_beats_truth/
├── index.html
└── README.md
```

> これは「真実を何％見ているか」をそのまま比較する装置ではありません。同じ事後分布から **最もありそうな状態を一つ選ぶ判断** と **適応度を確率で平均する判断** を比較します。論文の数値例・意思決定則を実装し、個体群更新の具体的仕様と遊びのための拡張を明示しています。著者の元プログラム、原論文全図、FBT定理の一般的な確率主張を完全再現したものではありません。

## すぐ動かす

`index.html` をブラウザで開き、**「開始」** を押してください。外部通信は不要です。「設定を適用して開始」は、編集した設定で初期状態から実行するボタンです。

ローカルHTTPで開く場合は、このフォルダで次を実行します。Pythonはこの任意の配信方法に使うだけで、アプリ自体の依存関係ではありません。

```bash
python3 -m http.server 8000 --bind 127.0.0.1
# ブラウザで http://127.0.0.1:8000/ を開く
```

## 出典をどう調べ、何を実装したか

### 中心資料：指定論文

Prakash, C., Stephens, K. D., Hoffman, D. D., Singh, M., & Fields, C. **Fitness Beats Truth in the Evolution of Perception.** *Acta Biotheoretica*, 69, 319–341 (2021). オンライン公開は2020年11月24日。DOI: `10.1007/s10441-020-09400-0`。

[指定のPubMed](https://pubmed.ncbi.nlm.nih.gov/33231784/) · [出版社・公開されている付録](https://link.springer.com/article/10.1007/s10441-020-09400-0) · [著者公開稿 PDF](https://sites.socsci.uci.edu/~ddhoff/FitnessBeatsTruth_apa_PBR.pdf) · [別の著者公開稿 PDF](https://sites.socsci.uci.edu/~ddhoff/FBT-7-30-17)

この研究は、進化ゲーム理論とベイズ意思決定理論によってTruthとFitness-onlyを比較します。本実装は、出版社ページの付録で確認できる数値と、著者公開稿の戦略定義・資源ゲーム・有限集団Moran過程の説明を参照しました。公開稿は出版版そのものと同一ではないため、数値例は出版社側と照合しています。

### 「コンピュータで生存競争させた」という話の先行研究

Mark, J. T., Marion, B. B., & Hoffman, D. D. **Natural selection and veridical perceptions.** *Journal of Theoretical Biology*, 266, 504–515 (2010). DOI: `10.1016/j.jtbi.2010.07.020`。

[PubMed](https://pubmed.ncbi.nlm.nih.gov/20659478/) · [出版社](https://www.sciencedirect.com/science/article/abs/pii/S0022519310003772)

この先行研究には解析解とMonte Carloシミュレーションがあり、完全混合された無限集団の進化ゲームが扱われています。したがって「シミュレーション研究」と指定の「FBT定理の論文」は関係しますが、同じものではありません。本アプリは、先行研究のコスト・速度差を含む全設定を複製するのではなく、**指定論文のベイズ的な比較を中心** にしています。

## 遊び方と画面

アリーナの丸・三角・六角形は実際の個体に対応します。色だけでなく形でも区別できます。光の軌跡は実際に抽選された親から置換先へ伸び、戦略が変わると発光・消滅の演出が起きます。個体をクリックすると、そのスロットにいる個体の識別番号、戦略、誕生世代、出生回数、系統を表示します。**移動、位置、距離、形、音は選択計算に入りません。**

| パネル | できること |
|---|---|
| ライブ観察 | 個体群アリーナ、勢力図、対戦行列、独立した採餌アニメーション、消失・再出現・固定のログ |
| 知覚を解剖 | 適応度と事前確率の図、信号ごとの事後分布、MAP評価と期待利得、全確率行列の閲覧・編集 |
| 自分で選ぶ | 標準12問の採餌ミニゲーム。隠れた状態の候補と確率を見て選び、期待効率・実現利得・連続最適選択を比較 |
| 反復実験 | 独立乱数種で同じ環境を反復。F/T/Hの吸収固定、未吸収、95%区間、理論上の固定確率、CSV出力 |
| 論文と実装 | 出典、数式、仮定、拡張、限界、内蔵の数値テスト |

**環境を反転** は現在の `fitness` 配列を逆順にします。確率は変更しません。**少数派を再導入** は最多戦略の個体を少数戦略へ置き換えます。いずれも自然進化ではなく外部介入として、イベント時刻とともに実験記録へ残ります。両戦略は反転後の適応度を即座に利用し、未知の環境への再学習はしません。

開始・一時停止、1イベント送り、100世代の早送り、速度変更、同じ種でリセット、乱数種の変更があります。音は初期状態でOFFです。キーボードは `Space` が開始/停止、`N` が1イベント、`R` がリセット、`?` が説明。フォームや操作ボタンなどにフォーカスがある間は、ショートカットを発動させません。

## 数学モデル

### 1. 共通の情報と二つの判断

世界状態を `w ∈ W`、感覚信号を `x ∈ X`、事前確率を `μ(w)`、感覚チャネルを `K[w][x] = P(x|w)`、適応度を `f(w)` とします。どの戦略も同じ `μ, K, f` を知っています。

```text
P(x)       = Σ_w μ(w) K[w][x]
P(w | x)   = μ(w) K[w][x] / P(x)

w_MAP(x)   = argmax_w P(w | x)
S_T(x)     = f(w_MAP(x))
S_F(x)     = Σ_w P(w | x) f(w)
S_H(x)     = (1 − α) S_F(x) + α S_T(x)
```

利用可能な資源のうち、自分の `S` が最大の信号を選びます。Fは実際の隠れた状態を直接見るわけではなく、不確実性を残した期待値で判断します。Tも適応度を知らないわけではありませんが、状態をMAP点推定に縮約してから評価します。

MAPの同率は最小の状態番号に決めます。資源評価の同率は等確率です。後者の浮動小数点比較では `1e-10 × max(1, |最大評価|)` を許容します。`P(x)=0` の信号は選択肢から除きます。

`α` はHybridの評価の混合係数であって、「真実を知る確率」「情報量の割合」ではありません。連続的にαを動かしても、最大の選択肢が変わらなければ行動・利得は変わりません。特に標準の2信号では、HがFまたはTと同じ行動になる範囲があります。

### 2. 論文の数値例

出版社の付録のデータを初期状態にしています。

| 状態 | μ(w) | P(x₁\|w) | P(x₂\|w) | f(w) |
|---|---:|---:|---:|---:|
| w₁ | 1/7 | 1/4 | 3/4 | 20 |
| w₂ | 3/7 | 3/4 | 1/4 | 4 |
| w₃ | 3/7 | 1/4 | 3/4 | 3 |

```text
P(x₁) = 13/28                 P(x₂) = 15/28
P(w | x₁) = [1/13, 9/13, 3/13]
P(w | x₂) = [1/5,  1/5,  3/5]

S_T(x₁) = 4                  S_T(x₂) = 3
S_F(x₁) = 5                  S_F(x₂) = 6.6
```

したがって自由に選べるとき、Tはx₁、Fはx₂を選びます。[数値の出典：出版社の付録](https://link.springer.com/article/10.1007/s10441-020-09400-0)。リンク先のページ内で「Appendix」を参照してください。

### 3. 競争から期待利得行列へ

各有効信号につき資源が1個ずつあるゲームです。各信号の資源の隠れた状態は、その信号に条件づけた `P(w|x)` に従います。**資源の信号自体をP(x)から毎回抽選する、別のゲームではありません。**

先手になる確率は双方1/2。先手は最も高く評価する資源を取り、後手は残りから選びます。同率の行動も含めて期待値を解析的に平均し、行が自分・列が相手の利得行列 `A` を作ります。標準例から本アプリが導く行列は次のとおりです。

| A | 相手F | 相手T |
|---|---:|---:|
| 自分F | 5.8 | 6.6 |
| 自分T | 5.0 | 5.8 |

同じ戦略同士なら5と6.6を半分ずつ受け取り、平均5.8。F対Tは欲しい資源が異なるため、Fは6.6、Tは5です。`exclusive=false` は資源を共有できる拡張で、行列のF行はすべて6.6、T行はすべて5になります。

「採餌をスローモーションで」の得点は、別乱数で隠れた状態を抽選した**実現利得**です。このデモの得点を出生に直接足してはいません。集団の出生には上の**期待利得行列**を使います。デモは最大12資源を描画し、選ばれた資源を必ず含め、残りの数を表示します。

### 4. 有限集団のMoran更新

総個体数 `N` は一定です。存在する戦略 `i` の平均利得と出生重みを次のように計算します。

```text
π_i = Σ_j (n_j − 1{i=j}) A_ij / (N − 1)
b_i = max(0, 1 − s + s(π_i − c_i))

P(親の戦略=i) = n_i b_i / Σ_j n_j b_j
P(死亡戦略=j) = n_j / N
```

自己との対戦は除きます。存在しない戦略の出生確率は0ですが、上部の利得差を表示するための反実仮想利得はN個体を相手として計算します。表示される利得差・行列は**費用控除前**で、実際の出生重みとは異なります。重みを非負に切り詰め、集団全体の出生重みが0なら個体ごとに等確率の出生へ戻します。負の重みを許す設定の処理は、本アプリの拡張仕様です。

親と死亡個体は独立に選び、親自身が置換されることもあります。通常は親の戦略を継承しますが、`mutation` の確率で、有効な他の戦略へ等確率で変異します。無変異のとき0個体の戦略は自発的に戻りません。

**1世代 = N回の出生・死亡イベント**。世代ごとの一斉交代ではありません。初期の百分率は最大剰余法で整数個体数に変換し、端数同率はF、T、Hの順に処理します。

### 5. 固定・反復の解釈

変異0で全個体が同じ戦略になった状態を「吸収固定」と呼びます。変異があると単一化しても他戦略が再出現し得るため、吸収固定ではありません。ライブ実験は標準では吸収固定または上限世代で止まります。

反復実験は**現在の環境・費用・選択設定と、設定上の初期比率**を使います。ライブの途中の個体数からは始めません。環境を生成し直すのではなく、同じ世界のまま出生・死亡の乱数を変えます。ライブ個体群とその乱数状態は変更しませんが、実行中のライブは一時停止し、終了後も停止状態にします。

上限まで吸収しなかった試行は `censored`（未吸収）です。T勝利には数えません。表示するWilson 95%区間は、**上限内にFが吸収固定する確率**に対する二項比率の区間です。未吸収が残る場合、それを最終固定確率の区間と読み替えてはいけません。変異ありなら全試行が原則として未吸収になります。中止時は完了済みの試行だけを集計し、途中の試行は除外します。

二戦略・無変異・すべての内部状態で正の出生重みという条件では、Moran連鎖の最終F固定確率も計算します。Fがk個体のときの出生重みを `b_F(k), b_T(k)` とすると、初期i個体からの確率は以下です。

```text
γ_k = b_T(k) / b_F(k)
ρ_i = (1 + Σ_{k=1}^{i−1} Π_{j=1}^{k} γ_j)
      / (1 + Σ_{k=1}^{N−1} Π_{j=1}^{k} γ_j)
```

積は対数で計算し、オーバーフローを避けます。中立なら `ρ_i=i/N`。ライブのこの表示は初期化・介入時点の個体数を基準にし、行列下にその個体数を明記します。毎フレーム変化する現在確率の表示ではありません。

## 全パラメータ

**41項目**です。通常の40項目は設定欄から、任意の世界データ `customWorld` は「全設定 / 世界データをJSONで編集」から指定できます。数値欄は下記範囲の任意の有限数、整数指定の欄は任意の整数を受け付けます。設定を省略すると標準値を補い、未知のキーや不正値はエラーにします。

`model="paper"` では生成用の項目を使わず、論文データを固定します。`model="custom"` では配列の長さから状態数・信号数を決めます。生成用のパラメータは `model="generated"` のときだけ有効です。

| `speed` | `0.5` | 0.05〜5 | 実行中は上の速度スライダーで変更可能。系列自体は変わりません。 |
| `effectLimit` | `75` | 0〜300、整数 | 描画の負荷制限。0では置換アニメーションなし。計算は省略しません。 |
| `effectSeconds` | `0.65` | 0.1〜2 | 出生の軌跡・消滅・発光が残る時間。 |
| `motion` | `true` | `true` / `false` | 位置は演出のみ。OSの動きを減らす設定も尊重します。 |
| `glow` | `true` | `true` / `false` | 影の描画負荷が高い環境ではOFF。 |
| `sound` | `false` | `true` / `false` | ブラウザで合成。開始などの操作後に有効化。外部音源なし。 |
| `volume` | `0.12` | 0〜1 | マスター音量。 |
| `duelSeconds` | `4` | 1〜15 | 選択ルールの独立した視覚デモ。集団の乱数・選択に影響しません。 |

| `historyLimit` | `10000` | 100〜100000、整数 | 超過すると最も古い行から削除。CSVにも保持分のみ出力。 |

### 任意の世界：customWorld

41番目のキー `customWorld` の標準値は `null`。任意の世界を指定するときは `model="custom"` とし、次の3配列を与えます。下は論文例と同じ世界を直接指定するJSONです。ほかの項目を省略しても動作します。

```json
{
  "model": "custom",
  "seed": "my-world-01",
  "population": 160,
  "initialF": 50,
  "customWorld": {
    "prior": [0.14285714285714285, 0.42857142857142855, 0.42857142857142855],
    "likelihood": [[0.25, 0.75], [0.75, 0.25], [0.25, 0.75]],
    "fitness": [20, 4, 3]
  }
}
```

`prior` は状態ごとの事前確率、`likelihood` は行が状態・列が信号、`fitness` は状態ごとの適応度です。状態数は2〜64、信号数は2〜32。`prior` の合計および `likelihood` の各行和は1で、許容差は `1e-9`。確率は0〜1、適応度は0〜1,000,000の有限数です。正の出現確率を持つ信号が2つ以上必要です。未知の世界データのキー、長さの不一致、NaN相当の値、空配列などは拒否します。

全設定JSONの「現在の世界をcustomとして挿入」から、生成した世界を固定データとして取り出せます。複数の条件で同じ事前分布・適応度を厳密に保つ比較にも使えます。

### 組み合わせの制約と生成則

初期Fと初期Hの合計は100%以下。Hybrid無効時の初期Hは0。`rescueCount ≤ population`。生成適応度の下限と振幅の合計は1,000,000以下。`identity` チャネルでは状態数と信号数を一致させます。

状態の正規化位置を `z=w/(|W|−1)`（ここではwは0始まりの番号）として、生成世界は次のルールです。

```text
bands:      map(w) = floor(w × |X| / |W|)
scrambled:  map(w) を各状態ごとに等確率で抽選
identity:   map(w) = w

K[w][x] = (1 − noise) 1{x=map(w)} + noise / |X|

uniform prior: μ(w) = 1/|W|
random prior:  μ(w) ∝ U_w ^ priorPower

f(w) = payoffFloor + payoffScale × g(z)

rugged: g(z) = 一様乱数
hump:   g(z) = exp(−(z−peakCenter)² / (2 peakWidth²))
linear: g(z) = z
flat:   g(z) = 1
```

`identity` でもノイズが正なら完全情報ではありません。`noise=1` では信号が状態と独立になります。無ノイズの圧縮やランダム対応で出現確率0の信号ができた場合、その信号は競争に参加しません。生成結果に有効信号が1つしかないときは、別の種・信号数・ノイズなどに変更してください。

世界生成の乱数は事前分布・対応・適応度で同じ系列を順に使うため、チャネルの種類や状態数を変えると、同じ種でも他の生成データが変わり得ます。完全に一要因だけ変える比較には、生成後の世界をcustomへ固定してください。

## 保存・共有・再現性

### 保存先とファイルの違い

| 操作 | 内容 |
|---|---|
| 設定保存 | 設定欄の値をJSONへ出力。未適用の編集も対象 |
| 読込 / 全設定JSON | JSONを検証して設定欄へ反映。実行には適用ボタンが必要 |
| 設定を共有 | **適用済み設定と現在の世界**をURLフラグメントへ格納。反転済みの世界はcustom化 |
| ライブのCSV | 保持している個体数・比率・利得・出生重み・世界版番号・記録理由の履歴 |
| 実験記録JSON | 初期/現在の世界、設定、イベント数、個体数、乱数状態、保持履歴、介入、観察ログ、反復の条件と完了済み結果 |
| 反復のCSV | 試行番号、種、終了世代、F/T/H個体数、固定/未吸収、上限世代 |

実験記録JSONは**解析用スナップショット**で、設定の読込から実験途中へ復元する機能はありません。共有URLも途中の個体数や介入履歴は含まず、その環境・初期比率から新しく開始します。設定のJSONは1MBまで、共有フラグメントは読込時に200,000文字までです。ファイルURLを別端末へ送っても相手の同じ場所にHTMLがあるとは限らないため、URL共有には公開ページを使います。

履歴は標準で1世代ごとに保存し、初期化・停止・介入・手動記録時にも保存します。`historyLimit` を超えると古い行を削除し、画面とJSONに削除数を示します。CSVにも保持分だけが出ます。観察ログは直近600件を保持し、画面は直近50件を表示します。再初期化すると履歴・介入・反復結果は消えるため、必要な記録は先に保存してください。

### 乱数と速度

文字列の種を32ビットへハッシュし、Mulberry32方式の疑似乱数を使用します。暗号用途ではありません。世界生成、出生・死亡、個体描画、採餌デモ、反復、ミニゲームを別の種へ分岐します。

```text
seed|world
seed|evolution
seed|render
seed|duel
seed|batch|試行番号              # 0始まり
seed|challenge-world|問題番号    # さらに世界生成の系列へ
seed|challenge-reveal
```

集団の1イベントでは、親戦略、変異の有無、変異先、死亡戦略の順に**常に4回**抽選します。変異が無効でも抽選回数を保ちます。描画や音、独立デモを変えても、この系列は消費しません。**同じバージョン・同じ世界と設定・同じイベント時刻の介入**なら、同じイベント数で同じ戦略別個体数を再現できます。実時間何秒後という比較ではありません。個体レベルの系統・配置・軌跡は独立の描画系列を使うため、表示条件間で一致する保証の対象外です。

処理が重くても、演出の上限を理由に出生・死亡計算を間引きません。早送りは演出を省き、計算を短い処理単位に分割します。バックグラウンドタブではライブ進行を行わず、復帰時に経過時間の埋め合わせもしません。反復もブラウザの描画タイミングを使うため、バックグラウンドでは止まるか遅くなります。大きな個体数・上限・反復数の組み合わせは長時間かかるため、中止操作を用意しています。

ブラウザ開発者コンソールからも実行できます。

```javascript
FBT.selfTest();

// 描画や実時間に依存せず、一定のイベント数だけ進める
FBT.reset({ ...FBT.defaults, seed: "test-001" });
FBT.advance(1000);
FBT.getState();

// 反復とは別に、集団の計算だけを利用する
const c = FBT.validateConfig({ population: 40, rescueCount: 4 });
const world = FBT.makeWorld(c);
const info = FBT.inferWorld(world, c.alpha);
const matrix = FBT.expectedMatrix(info, c);
const engine = new FBT.Engine(c, matrix);
for (let i = 0; i < 10000 && !engine.absorbing(); i++) engine.step();
console.log(engine.tick, engine.counts);
```

`FBT.Engine` は計算用の低水準APIで、アプリ側のライブ上限を自動適用しません。UIまたは `FBT.advance` は停止設定・ライブ上限を守ります。公開APIには設定検証、世界生成、推論、行列計算、固定確率計算も含みます。

実装時にはChromiumでHTMLを読み込ませ、6シナリオ、介入、JSON、共有、ミニゲーム、反復、描画個体数と計算個体数の一致、390 / 768 / 1920px幅のレイアウトを確認しました。Firefox・Safariの実機、および公開後のGitHub Pagesでの確認は別途必要です。JavaScript、Canvas 2D、標準のdialog要素などを利用します。OSの「動きを減らす」設定に応じて個体のゆらぎを抑制しますが、出生・死亡の状態表示は継続します。

## この実験から言えること・言えないこと

Fの評価は、定義された選択肢と情報のもとで期待利得を最大化します。だからといって、有限集団のすべての試行でFが固定するわけではありません。完全情報ではFとTが同じになり、選択強度0なら利得にかかわらず中立です。費用や環境や提示される資源を変えれば、別の問題になります。

ここでTruthと呼ぶのは**MAP点推定を使う特定の戦略**です。「現実を正しく理解しようとする知性全般」ではありません。事後分布を保って判断する科学的推論は、Fと同じ意思決定を行えます。またFは適応度と確率を既知としており、それらを獲得する費用や学習は表現していません。

一つの世界で何回出生・死亡を反復しても、「すべての適応度関数にわたる確率」の推定にはなりません。本アプリの固定率はFBT定理の一般的な確率下限ではなく、明示された有限集団モデルの量です。意識が宇宙の根源である、外界が存在しない、科学的知識は無効である、といった形而上学的な主張の検証にもなりません。

## 実装とプライバシー

Vanilla JavaScript、CSS、Canvas 2Dのみ。計算も設定読込もブラウザ内です。広告、アクセス解析、Cookie、localStorage、外部API、`eval`、外部スクリプトを使いません。効果音もWeb Audioで合成します。論文リンクを自分で開いた場合、その外部サイトへの通常のアクセスは発生します。

出典の論文PDF・図・著者のプログラムは同梱していません。アプリ独自のUI、描画、数値実装と、出典を明示したモデル説明で構成しています。
